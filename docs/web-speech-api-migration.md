# Web Speech API 迁移总结

## 迁移概述

项目已成功从 `say.js` 迁移到 Web Speech API，解决了中文语音播放乱码问题，并提供了更好的跨平台兼容性。

## 主要变更

- 支持中文语音自动检测和选择
- 包含错误处理和重试机制

#### `test-web-speech-api.js`

## 技术优势

### 1. 解决中文乱码问题
- **原因**：`say.js` 依赖系统 TTS 引擎，存在编码转换问题
- **解决**：Web Speech API 直接使用 UTF-8，无编码转换

### 2. 更好的跨平台兼容性
- **之前**：依赖系统 TTS 引擎，不同平台表现不一致
- **现在**：浏览器原生支持，统一体验

### 3. 性能提升
- **之前**：需要进程间通信（IPC）
- **现在**：直接在前端调用，响应更快

### 4. 功能增强
- **语音控制**：支持暂停、恢复、停止
- **语音检测**：自动检测可用语音
- **参数支持**：完整的语速、音调、音量控制

## 使用方法

### 1. 前端组件使用

```typescript
import { speechManager } from '@/utils/speech'

// 播放语音
const result = await speechManager.speak('你好，世界', {
  rate: 1.0,
  pitch: 1.0,
  volume: 1.0,
  lang: 'zh-CN'
})

// 停止播放
speechManager.stop()
```

### 2. 自动化流程使用

语音节点会自动使用 Web Speech API，无需额外配置。

### 3. 测试验证

1. **浏览器测试**：打开 `test-speech.html` 进行功能测试
2. **应用测试**：在语音配置组件中测试语音播放
3. **自动化测试**：运行包含语音节点的自动化流程

## 故障排除

### 1. 中文语音不工作
- 检查系统是否安装中文语音包
- 使用语音诊断功能检查可用语音
- 尝试使用"默认语音"选项

### 2. 语音播放失败
- 检查浏览器语音权限
- 确认系统音频设备正常
- 查看控制台错误信息

### 3. 语音列表为空
- 等待语音加载完成（通常需要几秒钟）
- 刷新语音列表
- 检查浏览器语音支持
